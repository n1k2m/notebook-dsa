# Notebook DSA

Консольное приложение на Go для хранения событий с реализацией и сравнением трёх структур данных:

* Binary Search Tree (BST)
* AVL Tree
* Hash Table

Pet-проект, представляющий собой записную книжку событий. Пользователь может создавать, искать, удалять и фильтровать записи. Основная цель проекта - изучение структур данных, анализ сложности алгоритмов и сравнение производительности различных подходов хранения информации.

# Реализованные структуры данных

## Binary Search Tree (BST)

Обычное бинарное дерево поиска без балансировки.

Особенности:

* хранение элементов в отсортированном порядке
* простой алгоритм вставки и поиска
* поддержка удаления узлов

Сложность операций:

| Операция | Средний случай | Худший случай |
| -------- | -------------- | ------------- |
| Поиск    | O(log n)       | O(n)          |
| Вставка  | O(log n)       | O(n)          |
| Удаление | O(log n)       | O(n)          |

При добавлении уже отсортированных данных дерево может выродиться в линейную структуру.


## AVL Tree

Самобалансирующееся бинарное дерево поиска.

AVL сохраняет высоту дерева за счёт автоматических балансировок после операций вставки и удаления.

Реализованы:

* вычисление высоты узлов
* балансировка дерева
* левый поворот
* правый поворот
* двойные повороты

Сложность операций:

| Операция | Сложность |
| -------- | --------- |
| Поиск    | O(log n)  |
| Вставка  | O(log n)  |
| Удаление | O(log n)  |

В отличие от обычного BST, AVL сохраняет стабильную производительность даже при отсортированном вводе.


## Hash Table

Хеш-таблица с разрешением коллизий методом цепочек.

Особенности:

* ключ строится на основе даты и времени события
* быстрый поиск по ключу
* поддержка вставки, поиска и удаления
* хранение нескольких элементов при коллизиях

Сложность операций:

| Операция | Средний случай | Худший случай |
| -------- | -------------- | ------------- |
| Поиск    | O(1)           | O(n)          |
| Вставка  | O(1)           | O(n)          |
| Удаление | O(1)           | O(n)          |


# Benchmark

Для сравнения структур данных был проведён тест поиска события по дате и времени.

Эксперимент:

* данные генерируются автоматически
* ищется последнее событие в наборе
* каждый поиск выполняется 10000 раз
* результат усредняется

Пример результатов:

| Структура  | 100 элементов | 1000 элементов | 10000 элементов |
| ---------- | ------------- | -------------- | --------------- |
| BST        | 1.708 µs      | 14.3 µs        | 143.763 µs      |
| AVL Tree   | 199 ns        | 112 ns         | 100 ns          |
| Hash Table | 97 ns         | 93 ns          | 82 ns           |

Результаты зависят от железа, версии Go и условий запуска. Таблица показывает только один из вариантов измерений.

## Выводы

* BST показывает ухудшение производительности на отсортированных данных из-за потери баланса.
* AVL сохраняет стабильную скорость поиска благодаря балансировке.
* Hash Table обеспечивает минимальное среднее время доступа благодаря прямому обращению по ключу.

Запуск benchmark:

```bash
go run ./benchmark/
```
